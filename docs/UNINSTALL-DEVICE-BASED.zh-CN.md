# 按设备现状卸载，不依赖原安装事务

2026-11-02。E5、MU300、U30 Pro 使用同一入口；保留各自的存储和启动适配器。

## 用户流程

在有 root 的 Android 中选择“卸载并归还空间”，检查计划后执行。
不需要找到、导入或选择原安装记录，也不根据历史安装记录推断 Android 原容量。
工具直接核实当前 GPT、OpenWrt 文件系统标记、启动镜像、userdata 及解密映射。
只归还紧邻 userdata 的 OpenWrt 范围，不相邻时释放为未分配空间；不会吞并其他分区。
无法保数据时仍必须经过单独的清空数据确认，通信失败不能变成格式化理由。

原安装记录缺失、损坏或容量冲突都不能阻止这一设备检测流程。
先前拒绝 root、随后授权，仅影响是否已具备操作权限，不能当作数据被重建的证据。
执行前尚未获得 root 时等待授权，不写卸载请求，也不反复准备离线启动。

## 自动接续与内部恢复文件

中断后可重新进入卸载。工具自动寻找本次卸载留下的恢复检查点，按存储身份、
Android 槽位及完整 GPT 快照核实进度；无需用户进入安装记录管理器选择事务。
无线 ADB 地址变化可以重新绑定同一硬件。旧卸载记录不能接管后来重装的系统。
其他进程正在执行时，设备锁阻止覆盖它的恢复信息。

自动备份和写入检查点仍保存于工具自己的目录，用于断电恢复；这不同于要求用户
提供原安装事务。不能把“无需原事务”理解为不备份 GPT、启动镜像或取消设备身份检查。
已发生写入且恢复文件损坏时，仍不能凭一个分区名猜测并继续覆盖。

GPT 已归还但文件系统扩容未完成时，只处理剩余步骤，不再次删除分区或格式化。
已扩至目标容量的当前文件系统可以完成核验，不会因旧检查点的 UUID 永久卡住。
对于支持原厂 Android 挂载前 F2FS 扩容的设备，会重新核实当前映射和原厂扩容工具，
使用本次读取的 UUID、容量生成工作请求，不再把旧事务的 UUID 填回新请求。
原始检查点保留；若身份确实不同，完成页明确说明无法确认更早的数据保留情况，
不将一次新建文件系统误报为“原数据无损保留”。

尚未扩满、身份发生变化且只能通过离线原始分区工具扩容的情况，仍需要新离线计划；
不会重放内嵌旧 UUID 的离线工作镜像。它不是缺少原安装记录的限制。

## 回归范围

模拟测试覆盖原记录冲突、无记录、延迟授权、两套适配器、Android A/B、
eMMC/UFS 几何、未分配区域布局、断线与中断、分区归还后的继续扩容、
身份变化后的当前容量核验、原厂 F2FS 请求使用实时身份、设备锁及损坏检查点。
Linux 上用临时普通文件验证 GPT 写入、日志回放和扩容脚本，不操作实机分区。
